2) FILE SERVER (acces la distanță prin SFTP)
----------------------------------------------
Aplicația NU citește fișiere din folderul local al proiectului. Datele vin din baza
de date (SQL), iar fișierele JSON vin de pe file server, prin internet, prin SFTP.
Folderul `File-Server/` din repository e doar copia de referință/seed, nu sursa de rulare.

De ce SFTP și nu share SMB:
  - o cale UNC de forma \\server\share folosește OBLIGATORIU portul 445; nu poți pune alt port
    într-o cale UNC, deci redirecționarea 44545 → 445 nu ar funcționa de pe un client
  - portul 445 expus la internet e cel mai atacat port Windows, iar multe rețele
    (colegiu, hotspot mobil) blochează oricum 445 pe ieșire — nu s-ar conecta nimeni
  - SFTP merge pe un singur port, criptat, prin NAT, fără VPN și fără certificat TLS

Server: OpenSSH Server (funcție opțională inclusă în Windows 11), mod SFTP.
Folder rădăcină pe server:               C:\File-Server
Adresă de conectare (de la distanță):    sftp://188.237.68.25:44545
Adresă de conectare (local, pe server):  sftp://localhost:22
Cont dedicat (utilizator local Windows, NU Everyone, NU administrator):
  Login:   autogara_fs
  Parolă:  YW29s=k?Gp67h?!Ryb
  (parola asta rămâne lungă intenționat — contul e expus la internet și nu o tastează
   nimeni manual, stă în fișierul de configurare al aplicației)

Instalare pe server (PowerShell ca Administrator):
  Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
  Set-Service -Name sshd -StartupType Automatic; Start-Service sshd
  $p = Read-Host -AsSecureString "Parola autogara_fs"
  New-LocalUser -Name autogara_fs -Password $p -PasswordNeverExpires -UserMayNotChangePassword
  icacls C:\File-Server /grant autogara_fs:(OI)(CI)M

Configurare C:\ProgramData\ssh\sshd_config (la final, după linia Subsystem):
  Subsystem sftp internal-sftp
  Match User autogara_fs
      ChrootDirectory C:\File-Server
      ForceCommand internal-sftp
      AllowTcpForwarding no
      PermitTunnel no
  (restart: Restart-Service sshd)
  Efect: contul vede doar C:\File-Server, nu poate deschide shell și nu poate ieși în rețea.

Structura pe server (identică cu folderul din repo):
  /Autobuze/autobuz_{AutobuzID}.json
  /Harta/harta.json
  /Backup/Autobuze/AAAA-LL-ZZ/...
  /Backup/Harta/AAAA-LL-ZZ/...

În aplicație: proiectul Autogara.FileServer, bibliotecă SSH.NET (NuGet: SSH.NET).
Interfața rămâne aceeași (ReadAsync / WriteAsync); se schimbă doar implementarea,
din cale UNC în client SFTP.

  TCP  44545  →  IP-local-server:22        SFTP (OpenSSH), fișiere JSON

UDP 1434 (SQL Browser — nu e necesar, portul SQL e static).

Firewall Windows pe server (PowerShell ca Administrator):
  New-NetFirewallRule -DisplayName "SQL EPSI 14330" -Direction Inbound -Protocol TCP -LocalPort 14330 -Action Allow
  New-NetFirewallRule -DisplayName "SFTP OpenSSH 22"  -Direction Inbound -Protocol TCP -LocalPort 22    -Action Allow

Verificat înainte de configurare: IP-ul WAN afișat în panoul routerului trebuie să fie
188.237.68.25. Dacă acolo apare o adresă de tip 10.x.x.x sau 100.64–100.127.x.x,
ești în spatele CGNAT și port-forwarding-ul nu funcționează — se cere IP public
de la furnizor sau se folosește un tunel.
