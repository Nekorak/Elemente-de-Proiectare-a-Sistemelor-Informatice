2) FILE SERVER (acces la distanță prin SFTP)
----------------------------------------------
Aplicația nu citește fișiere de pe calculatorul pe care rulează. Datele vin din baza
de date (SQL), iar fișierele JSON vin de pe file server, prin internet, prin SFTP.
Pe laptopurile echipei nu există nicio cale locală de fișiere.

De ce SFTP și nu share SMB:
  - o cale UNC de forma \server\share folosește OBLIGATORIU portul 445; nu poți pune alt port
    într-o cale UNC, deci redirecționarea 44545 → 445 nu ar funcționa de pe un client
  - multe rețele (colegiu, hotspot mobil) blochează portul 445 pe ieșire, deci nici
    de acolo nu s-ar conecta nimeni
  - SFTP merge pe un singur port, criptat, prin NAT, fără VPN și fără certificat TLS

Server: OpenSSH Server, mod SFTP.
  OpenSSH Server e DEJA INSTALAT pe calculator
  (C:\Windows\System32\OpenSSH\sshd.exe, serviciul "sshd" există, StartupType Manual).
  Regula de firewall "OpenSSH SSH Server (sshd)" pe portul 22 există deja și e activă.
  Singurul pas rămas (PowerShell ca Administrator, o dată):
      Set-Service -Name sshd -StartupType Automatic
      Start-Service sshd

Folder rădăcină (pe server):

  Există deja, cu fișierele /Autobuze/autobuz_1..8.json și /Harta/harta.json.

  - în linia de comandă:   sftp -P 44545 "Sergiu Hanganu"@188.237.68.25

lucru se face din configurarea aplicației (calea de bază), nu din sshd_config.
